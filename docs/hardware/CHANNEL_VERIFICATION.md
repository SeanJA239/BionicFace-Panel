# 逐通道真机验证台账

用 `tools/jog_channel.py` 逐通道单动得到的实测记录。每行都注明证据与日期；
「待定」表示观察到了现象但还缺一个量或一个参照。配置修正只依据本表的
「已确认」行，修正落在 `raspi/config.py` 后经 `export_config_json.py` 再生成
`motor_config.json`。

## 坐标系与读数约定

- **方向一律用观察者坐标系记录**(「你的左/右」,即站在机器人对面的人的左右),
  因为现场报告天然是这个坐标系。翻译关系:面对面时观察者的左 = 机器人自身
  的右。MediaPipe 混合形状名(eyeLookOutRight 等)和通道名(eye_right_* 等)
  用的是机器人自身坐标系,写代码时要做这一步翻译。
- **角度一律用 A(applied)**:面板滑条显示 L(logical),点动工具与帧日志是
  A,带 offset 的通道两者不等(如 ch8 差 5 度)。
- 台账里「已确认并落地」指该条目处理完毕(关单),不是停用通道。

## 待补测量

**ch8**:已裁决。死区精确起点不再追 -- max 钉在正视值本就正确:死区里的
命令是「指令变、外观不变」,会污染数据集;残余行程可忽略。通道成为单向
(同 ch0)。读数约定教训:面板显示 L(logical)、点动工具与帧日志是 A(applied),
ch8 的 offset=5 使两者相差 5 度,**报数一律用 A**。

**ch12 参照系**:已裁决(方向值乘 -1),三处同步修正 -- control.rs 眨眼表、
driver 权重、本台账;渲染器无需改动(ch12 本就在 MIRRORED_CHANNELS,从推断
变为实测)。副产品:右下眼睑闭合行程从 0.278 变为 0.722,右眼眨眼幅度将明显
变大。

## 后续每通道要记的列

单动时逐通道补齐:带动的解剖部位 / 正方向的面部含义 / min·max 是否物理
极限(距离硬限还有多少) / 传动比(命令度数 : 端点毫米,脸皮装上前测) /
与孪生脸方向是否一致。
